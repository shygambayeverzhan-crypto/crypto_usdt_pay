# Railway: приложение, Telegram и PostgreSQL

Два сервиса: приложение из `Dockerfile.railway` и PostgreSQL с постоянным томом.
В контейнере приложения Supervisor запускает Apache, очередь уведомлений и Laravel scheduler.
`payments:tick` каждую минуту проверяет ограниченный пакет заказов через существующие проверки TRON.
Общий замок в PostgreSQL исключает параллельную обработку пакета во время смены контейнеров.
Redis и внешний cron не нужны. Не включайте Serverless/sleep для приложения.

## Настройки Railway

Подключите репозиторий и ветку с MVP. До слияния PR — `codex/trust-wallet-mvp`.
Задайте `RAILWAY_DOCKERFILE_PATH=Dockerfile.railway`, порт `8080`, healthcheck `/up`,
одну реплику и restart on failure. Старый `railway.json` не требуется: настройки задаются в Railway UI.
Создайте PostgreSQL в том же проекте и регионе. Используйте приватную ссылку на переменную:

```dotenv
DATABASE_URL=${{Postgres.DATABASE_URL}}
DB_SSLMODE=disable
RAILWAY_DOCKERFILE_PATH=Dockerfile.railway
PORT=8080
APP_URL=https://ваш-домен.up.railway.app
APP_KEY=base64:ВАШ_ПОСТОЯННЫЙ_СЛУЧАЙНЫЙ_КЛЮЧ
MAIL_MAILER=log
PAYMENTS_ENABLED=false
```

`DB_SSLMODE=disable` предназначен только для приватной сети Railway, не для внешней БД.
Ключ приложения генерируется один раз (`php artisan key:generate --show`) и сохраняется приватно
в Variables. Не меняйте его при каждом развёртывании.
Сессии, кеш и очередь по умолчанию используют PostgreSQL. Загрузки логотипов отключены:
диск контейнера временный. База требует резервных копий; их стоимость проверяется отдельно.

При старте `railway:prepare` ожидает PostgreSQL, применяет миграции, создаёт начальные настройки
только в пустой таблице. Для первого владельца добавьте приватно `ADMIN_NAME`, `ADMIN_EMAIL`,
`ADMIN_PASSWORD` (минимум 12 символов). Администратор создаётся только если пользователей ещё нет.
После первого успешного запуска удалите `ADMIN_PASSWORD`. Повторный старт не меняет пароли и лимиты.
`/up` подтверждает работу PHP после завершения инициализации, не готовность принимать реальные платежи.

## Telegram

Создайте отдельного бота через @BotFather. Токен в чат, GitHub и логи не отправляйте.
Добавьте в Variables приложения:

```dotenv
TELEGRAM_BOT_TOKEN=секрет_от_BotFather
TELEGRAM_BOT_NAME=username_без_собачки
TELEGRAM_WEBHOOK_SECRET=случайная_строка_минимум_32_символа
TELEGRAM_WEBHOOK_URL=https://ваш-домен.up.railway.app/telegram/webhook
TELEGRAM_AUTO_WEBHOOK=true
```

На старте приложение проверит, что токен соответствует имени бота, установит HTTPS webhook
и проверит его URL через Telegram. При ошибке запуск остановится без вывода токена.
Секрет webhook допускает A–Z, a–z, 0–9, `_` и `-`. Один бот должен обслуживаться только этим проектом.
После первого запуска отключите `TELEGRAM_AUTO_WEBHOOK`, если не нужно проверять его на каждом старте.

`/start` показывает инструкцию. Персональная ссылка заказа `/start pay_...` привязывает заказ
к первому приватному чату; `/status` показывает последние пять привязанных платежей.
Сообщение об оплате отправляется после проверок сети, квитанции, контракта, адреса, суммы и подтверждений.
Селлер связывает свой Telegram через настройки уведомлений в кабинете.

## Включение платежей

Сначала выполните приёмку Nile: отдельная БД, тестовый контракт и адрес; затем отдельная mainnet-БД.
Настройки сети и команды публичного адреса описаны в `DEPLOY-VPS.md` и `MVP-ARCHITECTURE.md`.
Seed/private key не нужны. В Railway Console выполните `php artisan payments:configure-address email_владельца`.
Проверьте правильную оплату, недоплату, чужую сеть, повтор txid, перезапуск, восстановление после сбоя API,
уведомление Telegram и разграничение владельца/селлера. Только после этого `PAYMENTS_ENABLED=true`.
Создание новых заказов блокируется, если успешная проверка планировщика старше пяти минут.
Уведомление о готовности scheduler без активных заказов не является проверкой подключения к TRON.

## Стоимость и ограничения

Railway расходует включённый кредит за RAM/CPU/диск/трафик; постоянная работа не гарантированно бесплатна.
Новый тариф не требуется, если уже доступен действующий план, но расход может превысить включённый кредит.
Контролируйте Usage и задайте согласованный лимит. Лимит рабочего пространства может остановить и другие проекты.
Сначала тестовый запуск, затем оценка фактического расхода. 1 реплика, Apache максимум 8 процессов.

GitHub Actions проверяет сборку, bootstrap PostgreSQL, реальное выполнение scheduler, сохранность данных
после перезапуска и отказ webhook без секрета. Это не заменяет живую приёмку Telegram и TRON.
